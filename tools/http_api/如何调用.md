# 怎么调用手机上的本地 AI（3 步）

手机上的「qidian编辑器」内置了一个 HTTP API。手机和电脑连同一个 WiFi，电脑就能直接问它。

**带 API key 验证**：对话接口需要 key（在 App「关于」页查看），没有 key 或 key 错会返回 401。

---

## 给 Agent / 客户端配置（OpenAI 兼容，最常用）

如果你的 Agent、ChatBox、LobeChat、OpenWebUI 等支持"自定义 OpenAI 接口"，直接填三个值：

| 配置项 | 值 |
|---|---|
| Base URL | `http://<手机IP>:9999/v1` |
| API Key | App「关于」页查看（形如 `qd-xxxxxxxx`） |
| 模型名 | `qwen2.5-1.5b-mnn` |

> key 首次启动自动生成，存在手机里，重启不变；换 key 只能清 App 数据后重生成。

**关键第 1 步：看 key 和地址**——打开 App → 点右上角头像 →「ℹ️ 关于」：

```
── 给 Agent 配置（OpenAI 兼容）──
Base URL: http://192.168.3.4:9999/v1
API Key: qd-f20e101b32414ed4aee03bc3
模型名: qwen2.5-1.5b-mnn
```

**注意**：如果「关于」里显示的 IP（如 192.168.137.x）你的电脑连不上，
而手机 WiFi 实际 IP 是 192.168.3.4，就用实际能 ping 通的那个 IP（手机可能有多个网卡）。

**验证 OpenAI 接口（一行命令）**：

```bash
curl -X POST http://192.168.3.4:9999/v1/chat/completions \
  -H "Authorization: Bearer qd-f20e101b32414ed4aee03bc3" \
  -H "Content-Type: application/json" \
  -d '{"model":"qwen2.5-1.5b-mnn","messages":[{"role":"user","content":"你好"}]}'
```

支持 `stream: true`（SSE 流式）。多轮 messages 会按角色拼接喂给本地模型。

## 第 1 步：拿到手机 IP

**方法 A（最省事）**：打开 App → 点右上角头像 →「ℹ️ 关于」，里面直接写着 Base URL。

**方法 B**：手机「设置 → WLAN → 当前网络」看 IP。端口固定是 `9999`。

下面的例子都用 `192.168.3.4`，换成你自己的。

---

## 第 2 步：先用浏览器验证（不用写代码）

电脑浏览器打开（这个不需要 key）：

```
http://192.168.3.4:9999/health
```

看到类似下面的内容就说明通了：

```json
{"ok":true,"service":"qidian-minios","version":"3.0","ai":true,"model":"qwen2.5-1.5b-mnn","uptime":128,"chats":0,"lan":"192.168.3.4:9999"}
```

`"ai":true` = 模型已就绪可以问；`false` = 正在加载，等 3 秒再刷新。

再打开 `http://192.168.3.4:9999/` 会看到一个说明页（含 key 用法）。

---

## 第 3 步：调用对话接口

### curl（Windows 用 Git Bash 或 PowerShell 都行）

```bash
curl -X POST http://192.168.3.4:9999/chat \
  -H "Authorization: Bearer qd-f20e101b32414ed4aee03bc3" \
  -H "Content-Type: application/json" \
  -d '{"prompt":"你好，用一句话介绍你自己"}'
```

返回：

```json
{"ok":true,"reply":"你好！我是运行在奇点OS上的本地AI助手...","model":"qwen2.5-1.5b-mnn","ms":3821,"chars":42}
```

> PowerShell 里 `curl` 是 `Invoke-WebRequest` 的别名，双引号转义很麻烦。
> 直接用 `powershell -File tools\http_api\test_api.ps1 -Host 192.168.3.4` 更省事。

### Python

```python
import requests

KEY = "qd-f20e101b32414ed4aee03bc3"   # 换成你自己的
r = requests.post("http://192.168.3.4:9999/chat",
                  json={"prompt": "你好"}, timeout=120,
                  headers={"Authorization": f"Bearer {KEY}"})
print(r.json()["reply"])
```

没有 requests 也行：

```python
import json, urllib.request

req = urllib.request.Request(
    "http://192.168.3.4:9999/chat",
    data=json.dumps({"prompt": "你好"}).encode(),
    headers={"Content-Type": "application/json",
             "Authorization": "Bearer qd-f20e101b32414ed4aee03bc3"},
)
print(json.load(urllib.request.urlopen(req, timeout=120))["reply"])
```

### JavaScript（浏览器 / Node 18+）

```js
const KEY = "qd-f20e101b32414ed4aee03bc3";   // 换成你自己的
const r = await fetch("http://192.168.3.4:9999/chat", {
  method: "POST",
  headers: { "Content-Type": "application/json", "Authorization": "Bearer " + KEY },
  body: JSON.stringify({ prompt: "你好" }),
});
const data = await r.json();
console.log(data.reply);
```

接口带了 CORS 头，网页里直接调不会被跨域拦。

## 接口一览

| 方法 | 路径 | 鉴权 | 说明 |
|---|---|---|---|
| GET | `/health` | 不需要 | 服务与模型状态 |
| GET | `/` | 不需要 | 说明页（浏览器直接看） |
| GET | `/status` | 不需要 | 同 `/health` |
| POST | `/v1/chat/completions` | **需要** | OpenAI 兼容对话（推荐，Agent 直接用） |
| GET | `/v1/models` | **需要** | OpenAI 兼容模型列表 |
| POST | `/chat` | **需要** | 简单格式，body `{"prompt":"..."}` 或纯文本 |
| - | 端口 `8822` | 不需要 | 一行纯文本状态，给老脚本用 |

key 支持两种请求头写法（任选其一）：

```
Authorization: Bearer qd-xxxxxxxx
X-API-Key: qd-xxxxxxxx
```

`/chat` 的 body 三种写法都认：

```json
{"prompt": "你好"}
{"message": "你好"}
```
或者直接把纯文本当 body 发。

## 出错时看这张表

| 现象 | 含义 | 怎么办 |
|---|---|---|
| HTTP 401 `invalid_api_key` | 没带 key 或 key 不对 | 到 App「关于」页复制正确的 key |
| `{"ok":false,"error":"model_loading"}` HTTP 503 | 模型正在加载（首次约 2~3 秒） | 5 秒后重试，或先查 `/health` 的 `ai` 字段 |
| 连接超时 / 拒绝连接 | App 进程被系统杀了 | 手机上重新打开一次 App，服务会自动恢复 |
| 浏览器打不开页面 | 不在同一个 WiFi，或手机开了热点隔离 | 确认电脑和手机同一网段，关掉路由器的「AP 隔离」 |
| `/health` 通但 `/chat` 很慢 | 1.5B 模型在 CPU 上跑，正常 2~10 秒 | 正常现象 |

## 它跟以前的实现的区别

以前是把 HTTP 服务塞进 proot 容器（`microsrv.qds`）。proot 用 ptrace 拦截每个系统调用，
而且它自己是 App 的子进程——**App 一被系统冻结，容器里的服务就变成"端口还在监听、但永远不回包"**，
表现就是 `curl` 一直卡到超时。这也是之前老提示"容器未就绪"的根源。

现在 `LocalHttpServer` 直接跑在 App 进程自己的线程里：

```
电脑 curl  ──►  App 进程内的 ServerSocket  ──►  MnnEngine.infer()  ──►  返回
```

没有 proot、没有 WebView 轮询、没有临时文件。所以：

- 容器起不来 / 卡死，API 照样能用；
- App 里聊天也不再报"容器未就绪"；
- 模型没加载完会明确回 `503 model_loading`，而不是拿一个错误字符串当回答。

## 稳定性说明

- App 退到后台不影响服务（前台服务 + WakeLock 保活）。
- **熄屏后**部分国产 ROM（vivo OriginOS 等）会强制深度睡眠，这时请求可能不通。
  彻底解决要在系统设置里给 App 加白名单：
  - 设置 → 电池 → 后台耗电管理 → qidian编辑器 → 允许后台高耗电
  - i管家 → 应用管理 → qidian编辑器 → 允许自启动、允许后台运行
- App 进程被杀后，重新打开 App 即自动恢复（开机也会自启）。

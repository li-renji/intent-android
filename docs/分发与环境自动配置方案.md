# 奇点OS mini · 分发与环境自动配置方案

> 面向"把 App 发给任意用户 / 任意设备"这一场景。
> 核心命题：**用户拿到 APK 后，应当只做一件事 —— 点一下"下载模型"。其余全自动。**

---

## 0. 一句话结论

| 组件 | 体积 | 交付方式 | 理由 |
|---|---|---|---|
| APK（含 rootfs + 原生库） | ~48MB | 直接分发 | 安装包体积可控 |
| 模型权重（qwen2.5-1.5b-mnn） | **868MB** | **运行时下载** | 塞进 APK 会变成 916MB 安装包，无法分发 |
| 运行环境（proot/Alpine） | 28MB | 已在 APK 内（`assets/rootfs.tar`） | 首次启动自动解压，无需联网 |

模型绝不能打进 APK —— 这是整个方案的第一原则。

---

## 1. 首次启动时到底发生了什么

```
用户点开 App
   │
   ├─► 自动解压 rootfs.tar → files/rootfs/          （内置资产，离线可用）
   │
   ├─► 检查 files/models/qwen2.5-1.5b-mnn/
   │      ├─ 存在 → 加载 MNN 引擎 → 就绪
   │      └─ 缺失 → 自动进入下载流程（下节）
   │
   ├─► 下载模型
   │      ├─ 环境自检：架构 / 内存 / 存储空间
   │      ├─ 多镜像源依次尝试
   │      ├─ 断点续传（.part 文件 + Range 头）
   │      ├─ 进度实时推送到 UI（速度 / 剩余时间 / 百分比）
   │      └─ SHA-256 校验 → 原子替换
   │
   └─► 启动 AI 服务 + HTTP API + 容器
```

## 2. 模型自动下载（已实现）

### 2.1 代码位置

| 文件 | 作用 |
|---|---|
| `app/src/main/java/com/qidian/minios/ModelProvisioner.kt` | 下载器核心：多镜像 / 断点续传 / 校验 / 重试 |
| `app/src/main/assets/model_manifest.json` | 模型清单（版本、文件、镜像源）—— **运维只改这个文件** |
| `MainActivity.kt` | 调度 + 状态字段 + JS 接口（`startModelDownload` / `cancelModelDownload` / `checkEnvironment`） |
| `app/src/main/assets/ui/app.js` | `ModelDownload` 模块：进度条、速度、剩余时间、失败重试 |
| `LocalHttpServer.kt` | `GET /model/status` 供外部监控下载进度 |

### 2.2 关键设计

**多镜像自动切换**
`model_manifest.json` 里 `mirrors` 数组按序尝试，每个镜像内部重试 3 次（指数退避），全失败才换源。
用户不需要知道模型在哪 —— 这是"给别人用"最核心的一点。

**断点续传**
下载写入 `llm.mnn.weight.part`，续传时带 `Range: bytes=N-`。
服务端返回 200（忽略 Range）时自动从头下，返回 206 则接着下。
中途断网 / 切后台被杀 → 重试从断点继续，不浪费流量。

**完整性校验**
逐文件 SHA-256 + 整体权重校验。校验失败自动删除损坏文件并报错。
> 重要性：模型文件被截断会导致 MNN 加载时原生崩溃（和之前查的闪退同类问题），宁可明确报错也不要静默损坏。

**环境自检**（`preflight()`）
- CPU 架构：必须 `arm64-v8a`（原生库只有 aarch64）
- 内存：< 1.5GB 时明确提示
- 存储：需要 模型总量 + 64MB 余量，不足时提示清理

失败时返回**给用户看的中文说明**，而不是静默降级。

### 2.3 部署时必须做的事

#### 方案 A：直接用官方源（零运维，最快）

MNN 团队在 ModelScope 上发布了官方预转换好的模型，**国内直连、支持断点续传、免注册**：

```
https://www.modelscope.cn/models/MNN/Qwen2.5-1.5B-Instruct-MNN/resolve/master/
```

**这就是 `model_manifest.json` 当前的默认配置，开箱即用，你不需要自己搭 CDN。**

实测数据（2026-10-24，本机验证）：

| 项 | 结果 |
|---|---|
| Range 支持 | ✅ HTTP 206 + `accept-ranges: bytes`（断点续传可用） |
| 下载速度 | 5.1 MB/s → 868MB 约 **2.7 分钟** |
| 重定向 | ✅ 自动 302 到 `cdn-lfs-cn-1.modelscope.cn`，下载器已处理 |
| 免注册 | ✅ 无需 token，直接 GET |

> HuggingFace 的 `taobao-mnn/Qwen2.5-1.5B-Instruct-MNN` 内容相同，但**国内直连超时**，
> 不建议写进 mirrors 主位（可作为境外用户的后备源）。

**注意**：官方版用 `tokenizer.txt`，且 `llm_config.json` 没有 chat_template。
App 已做兼容（`AiService` 启动时若 `config.json` 缺 `tokenizer_file` 会自动补齐），
两种模型包都能直接加载。

#### 方案 B：自建 CDN（需要完全掌控版本时）

把 `model_manifest.json` 的 `mirrors` 换成你自己的地址：

```json
{
  "mirrors": [
    "https://cdn.your-domain.com/models/qwen2.5-1.5b-mnn",
    "https://oss-cn-beijing.aliyuncs.com/your-bucket/models/qwen2.5-1.5b-mnn"
  ]
}
```

**服务端目录结构必须与 `files[].path` 一致**：

```
<mirror>/config.json
<mirror>/llm.mnn
<mirror>/llm.mnn.json
<mirror>/llm_config.json
<mirror>/tokenizer.txt          ← 或 tokenizer.mtok，与 config.json 匹配
<mirror>/llm.mnn.weight        ← 868MB，主要流量
```

> ⚠️ 强烈建议给 `llm.mnn.weight` 填上真实 sha256 —— 这样能防 CDN 损坏、防传输截断、防被人替换。
> 用 `sha256sum llm.mnn.weight` 取值后填进 `files[]` 的 `sha256` 字段。
> 留空则跳过校验（仍会校验文件大小）。

#### 方案 C：自建版本（要 chat_template / tool calling 时）

当前手机上的模型包带完整 jinja chat_template（支持 `tools` / `tool_calls`），
而 ModelScope 官方版没有。如果要用这个版本：

1. 从手机 pull 出来：
   ```bash
   adb shell "run-as com.qidian.minios tar -cf /data/local/tmp/m.tar -C /data/data/com.qidian.minios/files/models qwen2.5-1.5b-mnn"
   adb pull /data/local/tmp/m.tar
   ```
2. 解包后按 `files[].path` 传到你的 CDN
3. 改 `model_manifest.json` 的 `files[]`（注意 `tokenizer.mtok` 而非 `tokenizer.txt`）
4. 更新 `total_bytes`

> App 当前走的是**自拼 prompt**（`[系统]…[用户]…`）而非 MNN 的 chat_template，
> 所以 chat_template 目前不参与推理；但它保留了未来切换到 messages 结构化接口的可能。

## 3. 三种交付模式（按场景选）

### 模式 A：在线分发（推荐，99% 的场景）

```
发 APK（48MB）→ 用户装 → 首启自动从 ModelScope 官方源下 868MB → 约 3 分钟 → 完成
```

**优点**：APK 小、更新快、**零运维**（不用自己搭 CDN）、模型版本可通过 manifest 热更新（不改 APK 就能换模型）
**缺点**：首次使用要下 868MB

**发布清单**
1. 构建 APK：`gradle assembleRelease`（记得配置签名）
2. 确认 `model_manifest.json` 的 `mirrors` 指向可用源（默认已是 ModelScope 官方源）
3. 重新构建 APK → 分发

### 模式 B：离线包（内网 / 无网环境）

```
发 APK + 发一个模型压缩包（或 U 盘 / 局域网共享）
→ 用户把模型包放到指定位置 → App 检测到直接校验加载，不走网络
```

实现方式：约定 `files/models/qwen2.5-1.5b-mnn/` 目录，
用 `adb push` 或文件管理器放入即可 —— App 检测到文件齐全就跳过下载。
> 这条路径**现在就已经可用**（`ensureModelProvisioned` 开头就是 `isReady()` 判断），
> 只是需要用 PC 端推文件：

```bash
adb push model_dir/ /data/data/com.qidian.minios/files/models/qwen2.5-1.5b-mnn/
```

### 模式 C：预置到系统分区（厂商预装 / 应用市场分发）

把模型放进 APK 的 `assets/`，首次启动解压到 `files/`。
- 代价：APK 变成 840MB，**无法上应用市场**（Google Play 限制 100MB / base APK 150MB）
- 只适合做"预装包"走系统刷机，不适合公开分发

## 4. 设备适配（"给其他设备用"）

### 4.1 硬性要求

| 项 | 要求 | 不满足时 |
|---|---|---|
| 架构 | `arm64-v8a` | 自检直接报错「本应用仅支持 arm64-v8a」 |
| 内存 | ≥ 2GB（推荐 4GB+） | 自检提示可用内存不足 |
| 存储 | ≥ 1.5GB 可用 | 自检提示清理空间 |
| 系统 | Android 8.0+ | 未验证 |
| 网络 | 首次下载需联网 | 可用模式 B 离线包 |

### 4.2 已知的设备相关坑（来自实测）

1. **vivo / 国产 ROM 的深度睡眠**
   App 已有前台服务 + `PARTIAL_WAKE_LOCK` + 静音音频通路保活，但部分 vivo/OPPO ROM 仍会挂起整机。
   → 建议在引导页提示用户开启"允许后台高耗电 / 允许自启动"。

2. **国产 ROM 的安装拦截**
   `adb install` 会被 `PackageInterceptActivity` 拦截，需要人工点确认。分发给普通用户走应用市场安装则无此问题。

3. **WiFi Direct 虚拟接口 IP**
   App「关于」页显示 IP 时应固定取 `wlan0`，不要随机挑接口（历史 bug：显示成 `192.168.49.1` 导致外部无法连接）。
   → **建议修复**：见 §6。

## 5. 一键部署脚本（给测试 / 批量装机用）

见 `tools/deploy_phone.sh`，做三件事：
1. 无线连上设备（adb pair / connect）
2. 安装 APK
3. 把本地模型目录推送到设备（跳过下载）

```bash
./tools/deploy_phone.sh 192.168.3.4 42811 /path/to/model_dir
```

## 6. 建议的后续改进（按优先级）

| 优先级 | 项 | 说明 |
|---|---|---|
| 高 | **修复 IP 显示 bug** | `LocalHttpServer.localIp()` 随机挑接口 → 固定优先 `wlan0` |
| 高 | 填真实 sha256 | manifest 里补全校验值 |
| 中 | 分渠道构建 | `flavor` 区分 `china` / `global`，用不同 CDN 镜像 |
| 中 | 模型版本热更新 | manifest 里加 `version`，App 检测到新版本自动提示更新 |
| 中 | 下载进度接入通知栏 | 前台服务 + Notification，用户切出去也能看到进度 |
| 低 | 量化模型选项 | 内存小的设备可下 0.5B 版本（~400MB） |
| 低 | WiFi 传输模式 | 手机与 PC 同一局域网时，走 HTTP 传输比走公网 CDN 更快 |

## 7. 常见问题

**Q：下载到一半断了怎么办？**
A：自动断点续传。重试时从断点继续，只重下缺失部分。UI 上点"重试下载"即可。

**Q：一直显示"下载中"但不动？**
A：先看手机网络是否正常。可用 `curl http://<手机IP>:9999/model/status` 查看进度；
如果 `state` 一直是 `checking`，说明环境自检没通过（多为存储空间不足）。

**Q：模型下载好了但引擎加载失败？**
A：看 `files/diag.txt`。多半是 sha256 不匹配导致文件损坏 —— 删除 `files/models/` 重下。

**Q：能不能让用户完全不用管？**
A：能。`ensureModelProvisioned` 在首次启动时自动触发，用户什么都不用点。
只是 868MB 的下载静默进行体验不好，所以 UI 上仍然给了显眼的按钮和进度。
